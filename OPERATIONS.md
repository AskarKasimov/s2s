# Обслуживание Qwen3-Omni: справочник администратора

Основной сценарий развёртывания с нуля находится в [README.md](README.md).
Этот справочник описывает дополнительные команды, переменные окружения, предварительную подготовку без GPU и диагностику.

Репозиторий настроен под **выделенную чистую NVIDIA GPU 80 ГБ** (A100 / H100).
Бюджет стадий `Qwen3-Omni` составляет **88% VRAM** (`0.60 + 0.20 + 0.08` в `deploy.yaml`), **12% VRAM** оставлено под системный запас CUDA и рабочие буферы. Модель принимает вопрос голосом или текстом, формирует ответ и синтезирует речь.

Используется готовая версия Qwen3-Omni от Intel с квантованием **INT4 W4A16** (`Intel/Qwen3-Omni-30B-A3B-Instruct-int4-AutoRound`):
основная языковая часть (`Thinker`) сжата до 4 бит, а голосовые стадии (`Talker` и `Code2Wav`) работают в `BF16` для сохранения качества русской речи.
Веса занимают около **26,3 ГБ**. Самостоятельно квантовать модель не нужно.
Версии модели, исходников и базового Docker-образа закреплены в файлах проекта (`versions.json`, `Dockerfile`, `constraints.lock`).

## 1. Проверка готовности хоста

На сервере должны быть установлены:
- Linux x86_64, предпочтительно Ubuntu 24.04 LTS.
- Выделенная NVIDIA GPU **80 ГБ**, без MIG; compute capability от 8.0 и поддержка BF16.
- Перед стартом свободно **не менее 90% VRAM (~72 GiB)** (карта не должна быть занята другими процессами).
- RAM 128 ГБ; свободное место: 40 GiB под веса и 40 GiB под Docker (минимум 80 GiB на общем диске, рекомендуется 150 ГБ).
- Драйвер NVIDIA **580.95.05 или новее** (внутри контейнера используется CUDA 13.0.2).
- Docker Engine, плагин Docker Compose v2, NVIDIA Container Toolkit, Python 3, Git, curl.
- Доступ сервера к GitHub, Docker Hub, PyPI и Hugging Face.

Проверьте в терминале сервера:

```bash
nvidia-smi
docker info
docker compose version
python3 --version
git --version
```

Все команды должны выполняться без ошибок и без `sudo`.

## 2. Настройка окружения (`.env`)

На стандартном однокарточном сервере создавать и менять `.env` **не требуется** — все значения по умолчанию уже настроены в `compose.yaml`.

При необходимости кастомизации скопируйте шаблон в корне репозитория:

```bash
cp -n .env.example .env
nano .env
```

Доступные параметры:
- `GPU_ID=0` — индекс выделенной карты 80 ГБ из `nvidia-smi`. Внутри контейнера выбранная карта всегда видна как устройство `0`.
- `S2S_PORT=8091` — внутренний порт движка `vLLM-Omni` (привязан к `127.0.0.1`).
- `S2S_API_PORT=8002` — внешний порт HTTP API (`/speech-to-speech`, `/chat`, `/health`, `/docs`, `/metrics`).
- `S2S_API_BIND=0.0.0.0` — интерфейс публикации HTTP API (`0.0.0.0` — доступен по сети, `127.0.0.1` — только локально на сервере).
- `S2S_DATA_DIR=./data` — каталог хранения весов модели. Для размещения на отдельном диске укажите абсолютный путь, например `/srv/qwen3-omni`.
- `HF_TOKEN=` — токен Hugging Face (обычно не нужен, так как модель публичная; заполняется только для обхода сетевых rate-лимитов HF).

## 3. Сценарии запуска

### Стандартный запуск с нуля одной командой
```bash
./run.sh check
./run.sh install
```
Скрипт проверит хост, соберёт образ, проверит вычисления CUDA/BF16 внутри контейнера, скачает 26,3 ГБ весов, проверит целостность всех 13 шардов `safetensors`, запустит контейнеры `omni` и `api` и выполнит сквозной тест генерации текста и речи (`output/test-answer.wav`, `output/api-answer.wav`, `output/api-chat-answer.txt`).

### Предварительная сборка и скачивание весов без участия GPU
Если нужно заранее собрать образ и скачать веса до освобождения GPU:
```bash
./run.sh build
./run.sh test
./run.sh prepare
```
Когда чистая GPU 80 ГБ готова, запустите сервис и проверку командой:
```bash
./run.sh deploy
```

## 4. Все команды `./run.sh`

Выполняются из корня репозитория:

| Команда | Действие |
| --- | --- |
| `./run.sh check` | Проверить ОС, драйвер, GPU ($\ge 90\%$ свободной VRAM), RAM, диски и порты |
| `./run.sh install` | Полный цикл установки с нуля «под ключ» (сборка, скачивание, старт, проверка аудио) |
| `./run.sh status` | Показать состояние контейнеров `omni` и `api` |
| `./run.sh logs` | Показать логи в реальном времени (`Ctrl+C` закрывает просмотр) |
| `./run.sh verify` | Повторить приёмочную проверку голосового и текстового тракта |
| `./run.sh stop` | Остановить контейнеры и освободить GPU (веса в `data/` сохраняются) |
| `./run.sh start` | Запустить сервис с уже скачанными весами (после `stop` или перезагрузки сервера) |
| `./run.sh deploy` | Проверить GPU, запустить заранее подготовленный комплект и прогнать `verify` |
| `./run.sh doctor` | Собрать полную диагностику в папку `reports/` |
| `./run.sh test` | Прогнать 39 unit-тестов и сетевой интеграционный тест HTTP API без GPU |

Прямой OpenAI-compatible API движка `vLLM-Omni` доступен локально на сервере по адресу `http://127.0.0.1:8091` (`curl --fail http://127.0.0.1:8091/health`). Для клиентских приложений рекомендуется использовать внешний HTTP API на порту `8002` (см. [API.md](API.md)).

## 5. Диагностика при сбоях

| Сообщение / ситуация | Действие |
| --- | --- |
| Недостаточно свободной VRAM ($< 90\%$) | Проверьте `nvidia-smi`, остановите посторонние процессы или контейнеры на целевой GPU и повторите `./run.sh install` |
| Драйвер слишком старый | Обновите драйвер NVIDIA до `>= 580.95.05`, перезагрузите сервер и выполните `./run.sh check` |
| Docker не видит GPU / `could not select device driver` | Настройте NVIDIA Container Toolkit (`sudo nvidia-ctk runtime configure --runtime=docker && sudo systemctl restart docker`) |
| Ошибка скачивания / HTTP 429 с Hugging Face | Повторите `./run.sh install` или `./run.sh prepare` — скачанные файлы сохраняются в кеше `data/`; при необходимости укажите `HF_TOKEN` в `.env` |
| Порт `8002` или `8091` занят | Если это уже запущенный Qwen — выполните `./run.sh verify`; иначе освободите порт или измените `S2S_API_PORT` / `S2S_PORT` в `.env` |
| `unhealthy` / таймаут / OOM | Выполните `./run.sh doctor` и проверьте `reports/omni.log` и `reports/gpu.txt` |

При любой ошибке `./run.sh` автоматически сохраняет дампы в `reports/` (`containers.txt`, `omni.log`, `api.log`, `gpu.txt`). Каталог `data/` со скачанными весами удалять не нужно.

## 6. Состав репозитория

- `compose.yaml` — запуск движка `omni` (на GPU) и HTTP-шлюза `api` (на CPU).
- `Dockerfile` — сборка детерминированного образа на базе `vllm/vllm-openai:v0.32.0` и `vllm-omni` (`9842ebc`).
- `deploy.yaml` — конфигурация трёх стадий (`Thinker`, `Talker`, `Code2Wav`) на одной GPU 80 ГБ (бюджеты `0.60 / 0.20 / 0.08`).
- `gpu_policy.json` и `gpu_policy.py` — проверка ёмкости карты ($\ge 76$ GiB), свободной памяти ($\ge 90\%$) и бюджетов стадий ($88\%$).
- `versions.json` и `constraints.lock` — зафиксированные ревизии модели, коммита `vLLM-Omni`, драйвера и Python-пакетов.
- `run.sh` — единый скрипт установки, управления и самодиагностики.
- `host_check.py` — предпусковая проверка хоста до скачивания тяжелых артефактов.
- `runtime.py` — проверка GPU внутри контейнера, скачивание и валидация весов, запуск `vllm serve --omni`.
- `api.py` — FastAPI-сервис (`POST /speech-to-speech`, `POST /chat`, `GET /health`, `GET /metrics`).
- `client.py` и `verify_api.py` — клиенты сквозной самопроверки синтеза и понимания речи.
