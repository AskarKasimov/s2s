# Требования к серверу для Qwen3-Omni (чистая GPU 80 ГБ)

Этот документ предназначен системному администратору, который подготавливает сервер с нуля.
Пошаговая инструкция развёртывания «с первой попытки» приведена в [README.md](README.md).

## Поддерживаемый профиль

| Компонент | Требование |
| --- | --- |
| ОС | Ubuntu 24.04 LTS, Linux x86_64 |
| GPU | Выделенная NVIDIA GPU 80 ГБ (A100 80 ГБ / H100 80 ГБ); compute capability от 8.0 и BF16, без MIG |
| Номер GPU | `0` на однокарточном сервере; минимум **90% (~72 GiB)** свободной VRAM перед запуском |
| RAM | 128 ГБ |
| Диск | Минимум 80 GiB (рекомендуется 150 ГБ) свободно для Docker, весов и результатов проверки |
| Драйвер NVIDIA | `580.95.05` или новее |
| ПО хоста | Docker Engine, Docker Compose v2 с `up --wait --wait-timeout`, NVIDIA Container Toolkit, Python 3, Git, curl |
| Права исполнителя | Запуск Docker без `sudo`, запись в каталог репозитория |
| Исходящий доступ | GitHub, Docker Hub, PyPI, Hugging Face и используемые ими хранилища артефактов |
| Входящий доступ | SSH для установки; TCP `8002` для клиентов API по правилам сети организации |

По умолчанию используется `GPU_ID=0` — чистая выделенная карта 80 ГБ.
В `deploy.yaml` доли памяти стадий Qwen3-Omni равны `0.60 / 0.20 / 0.08` — суммарно **88% карты (~70,4 GiB)**. Оставшиеся **12% (~9,6 GiB)** — системный резерв под контексты CUDA, активации аудиоэнкодера и декодера волны.
Перед запуском требуется не менее **90% свободной VRAM (~72 GiB)**; при меньшем объёме автоматическая проверка прекращает запуск до загрузки модели. Общая политика проверок хранится в `gpu_policy.json`.

В контейнере жёстко закреплены CUDA 13.0.2, vLLM 0.32.0, source commit `vLLM-Omni` (`9842ebc17cf1d9c6b440ecb6a79039162f68a1dd`) и версии Python-пакетов (`constraints.lock`). CUDA Toolkit на хосте отдельно устанавливать не требуется — достаточно драйвера NVIDIA версии `580.95.05` или новее.

Официальные руководства производителей для подготовки хоста (быстрые команды также приведены в [README.md](README.md#2-подготовка-чистого-сервера-с-нуля-если-на-сервере-ещё-нет-docker-и-драйвера)):

- [Docker Engine для Ubuntu](https://docs.docker.com/engine/install/ubuntu/)
- [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html)

## Проверка перед запуском

Клонируйте репозиторий, перейдите в его корень и выполните:

```bash
./run.sh check
```

Команда автоматически проверяет карту, драйвер, свободную видеопамять ($\ge 90\%$), оперативную память, диски, доступ к Docker и свободные порты (`8002`, `8091`). Доступ к GPU из контейнера и BF16 matmul отдельно проверяются самой установкой (`./run.sh install`) перед скачиванием модели.

После успешного `./run.sh check` достаточно выполнить `./run.sh install`; ручной выбор версий и настройка стадий не требуются.

## Дополнительные настройки

При нестандартной сетевой схеме, размещении кеша весов на отдельном диске или выборе другой физической карты на многокарточном сервере создайте `.env` по шаблону `.env.example`:

```bash
cp -n .env.example .env
```

Описание параметров `.env` и всех сервисных команд приведено в [OPERATIONS.md](OPERATIONS.md).
